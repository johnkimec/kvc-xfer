kvc-xfer

KV-cache blocks, from the prefill worker to the decode worker

The first layers leave before the last ones exist.

kvc-xfer moves paged KV cache between inference nodes. Decode names the destination blocks. Prefill pushes each finished layer range as a coalesced copy, and READY means those bytes have landed.

  • [0, 8) while [8, 16)the next range is still computing
  • 2 per layerdescriptors for a contiguous run
  • ~1.4 GiB/sloopback TCP, 128 MiB

Adjacent blocks become one copy.

build_block_descriptors emits one slice per block, per layer, per K or V. coalesce_descriptors merges a slice into the previous one only when the bytes abut in the source region and in the destination region.

The payload is not copied onto the wire.

The sender thread builds an iovec that points at the registered region and calls sendmsg. The only bytes allocated for the transfer are the 24-byte frame header. The peer’s reader recvs each chunk straight into the destination region.

Either call can arrive first.

expect() sends PREPARE and waits. publish() before that PREPARE shows up is queued, and it runs when the blocks arrive. The usual order is the other way around: decode has already called expect() by the time a layer range finishes. The layout fingerprint rides along in PREPARE, and a mismatch fails before any bytes move. abort() from either side drops the request, and the in-flight handles complete with Cancelled.

Loopback is the ceiling.

Apple M-series, one connection, 128 MiB per transfer. The TCP rows are the kernel socket path. LocalTransport is the same engine over memcpy, which is what two workers in one process get.

Push and pull take the same path. A real NIC wants a connection per queue, or a transport that is not TCP.
